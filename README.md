# 🎾 테니스윗 클럽 앱 (정기 모임 · 분기 대회)

빌드 없는 정적 웹 앱 (HTML/CSS/JS). GitHub Pages 로 배포됩니다.

구조: `index.html`/`admin.html` 은 바뀌지 않는 껍데기이고, `loader.js` 가 배포 시 생성되는 `version.json`(캐시 없이 읽음)의 버전을 붙여 `app.html`·`style.css`·`app.js` 를 불러옵니다. 그래서 새로 배포하면 브라우저·CDN 캐시와 무관하게 항상 최신 화면이 뜹니다. 화면 마크업을 고칠 때는 `app.html` 을 수정하세요.
→ https://koozinsong.github.io/tennisweet/

## 사용 흐름 (관리자)
1. **관리자 페이지** https://koozinsong.github.io/tennisweet/admin.html (또는 상단 🔐 관리자 버튼) 에서 비밀번호 입력
2. **① 선수** — 이름·성별·NTRP·합류/퇴장 시각 입력, 참가 여부 체크. 여러 명 일괄 추가: `이름, 성별, NTRP, 합류시각` 한 줄에 한 명
3. **② 대회 설정** — 개인전(기본, 파트너 로테이션 복식·개인 순위) / 팀전 / 고정조 대회, 팀 수, 코트 수, 시작·종료 시각, 경기 시간
4. **③ 팀 구성** — 팀전만 해당. 균등 배정(합류 시각·NTRP·성별 고려) 후 드롭다운으로 수동 조정. 개인전은 비어 있음
5. **④ 일정표** — 전체 일정 생성, 게임 스코어 입력. **현장 편집 모드**: 시간·코트 이동, 참가자 교체, 경기 추가/삭제, 충돌(⚠) 경고
6. **⑤ 순위·대진** — 개인전: 개인 순위(승률 → 경기당 평균 득실 → 승수 → 득게임, 경기 수가 달라도 공정) / 팀전: 팀 순위 + 개인 기록. 방문자는 상위 3명만, 상세는 관리자. 일정표 아래에 인당 경기 수 요약
- 선수가 바뀌면 **🎾 개인전 생성** 또는 **👥 팀전 생성** 버튼 한 번으로 재생성 (팀전은 팀 배정 포함)

## 개인전 편성 규칙
- 시간대마다 참석 가능 선수 중 경기 수 적은 순으로 코트×4 명 선발 (여성 수는 짝수로 보정)
- 혼복 코트(여성 1+남성 1 대 여성 1+남성 1) → 여복 코트 → 남복 코트 순으로 구성, 파트너·상대 중복 최소
- 2회 연속 휴식 회피(직전 시간대 휴식자 최우선), 남복·혼복 골고루(혼복 덜 한 남성을 혼복 코트에), 여복 최소 경기 수(설정, 기본 1) 보장
- **특별 규칙 (개인전, 대회 설정 → 관리자만)**: 혼복은 양쪽 남자 NTRP 동일(기본 켬, 하드 규칙) · 혼복 필수 대진(선수 2명 이름, 서로 상대편으로 1경기 강제) · 동일 NTRP 남복(예: 4 → NTRP 4 남자 4명만의 남복 1경기 강제). 필수 대진은 시도마다 무작위 시간대에 먼저 확정하고 나머지를 채우며, 일정표 아래 '특별 규칙' 줄에 충족 여부(✓/✗)가 표시됩니다.
- NTRP 균형(기본): 한 코트에서 양쪽 조의 NTRP 합 차이가 작은 조합 우선 (관리자 로그인 상태에서 생성할 때 반영). 팀전 코트 편성에도 동일

## 팀전 배정 규칙
- 합류 시각 구간별로 2명(강+약)씩 짝지어 팀에 넣어, 각 팀이 그 시간대에 복식 인원을 갖추도록 함 (코트 최대 활용)
- 팀 규모 → 구간 인원 → 여성 수 → 평균 NTRP 순으로 균형
- 일정: 시간대마다 코트별 팀 대 팀 복식 1경기. 경기 종류는 **남복·여복·혼복** 뿐이며 양쪽 조의 종류가 같아야 함. 경기 수 적은 선수 우선, 파트너 중복 최소, 같은 시간대 중복 배정 금지

## 데이터와 공유
- **원본 = `data/tournament.json`**. 페이지를 여는 모두가 이 게시본을 읽기 전용으로 봅니다 (선수 명단은 누구나 볼 수 있고 NTRP 열만 관리자에게 표시).
- 일반 주소는 항상 읽기 전용이고, 관리자 앱은 `admin.html` 에서만 실행됩니다(로그인은 탭 단위 세션). 관리자 편집 내용은 브라우저(localStorage)에만 저장됩니다.
- **🚀 게시하기**(권장): 관리자 페이지 상단 버튼. 이 브라우저가 GitHub Contents API 로 `data/tournament.json` 을 `main`(원본)과 `gh-pages`(서빙 사본)에 커밋합니다. 최초 1회 GitHub Fine-grained 토큰(이 저장소 Contents: Read and write 권한만)을 등록합니다. 토큰은 관리자 비밀번호로 암호화되어 브라우저와 게시본(`ghTokenEnc`)에 저장되므로, 다른 기기에서는 관리자 비밀번호만 입력하면 바로 게시할 수 있습니다. 게시본이 공개 파일이므로 관리자 비밀번호는 추측이 어려운 것으로 두세요. 방문자 페이지는 45초마다 게시본을 다시 읽어 자동 갱신됩니다.
- 수동 게시: **내보내기** → 받은 `tournament.json` 을 `data/` 에 덮어쓰고 `git push`. (또는 Claude Code 로 파일 직접 수정 후 push)
- 현장에서 즉시 공유: **🔗 공유 링크** — 현재 상태 전체를 링크에 담아 카톡 등으로 전달 (읽기 전용 스냅샷)
- **NTRP 는 관리자 비밀번호로 AES-GCM 암호화**되어 저장됩니다. 저장소 JSON 을 열어도 평문이 보이지 않습니다 (예외: 정기 모임 대진 균형용 `data/weekly/index.json` 의 `levels` 는 관리자가 '레벨 갱신'을 누르면 NTRP 기반 레벨이 숫자로 들어갑니다 — 누구나 대진을 만들 수 있게 하기 위한 선택). 비밀번호 변경은 `app.js` 와 `admin.html` 의 `ADMIN_HASH`(PBKDF2-SHA256, salt `tennisweet-v1-verify`, 120000회) 를 바꾸고, 기존 NTRP 는 새 비밀번호로 다시 입력해야 합니다. 게시본이 공개 파일이므로 비밀번호는 추측하기 어려운 것으로 두는 편이 안전합니다.

## 정기 모임 (주간 모임: 참석 체크 → 누구나 대진 생성 → 완료 체크)

- 화면: 첫 화면 **정기 모임** → 날짜 칩 → 이름을 눌러 도착·퇴장 시각 선택(참석 저장) → **대진 생성** 버튼 → 시간대별 카드, 카드를 누르면 완료(다시 누르면 취소), "남은 대진" 필터. 게스트는 [+ 게스트]로 그 날짜에만 추가(이름·남/여 필수). 참석이 바뀌면 "남은 시간대 다시 짜기"로 아직 시작하지 않은 시간대만 다시 만듭니다(그대로 둔 시간대의 완료 표시는 유지). **다시 섞기**는 전체를 새로 만들고 완료 표시를 모두 지웁니다. 최근 6회 모임에서 같이 뛴 파트너·상대는 벌점을 받아 다음 주에는 다른 사람과 붙습니다.
- 경기 수: 전원 같은 수가 목표(차이 1 이내). 일찍 와서 이미 뛴 사람은 공유 시간대에서 양보하고, 곧 퇴장하는 사람과 게스트는 먼저 배정합니다. 참석 시간대를 다 뛴 사람은 상한으로 봅니다.
- **조 조정**: 대진 카드 위의 **조 조정** 버튼 → 이름을 누르고 자리를 바꿀 사람을 고릅니다. 같은 코트 사람이면 조 구성이 바뀌고, 다른 코트 사람이면 서로 코트를 맞바꿉니다 — 그 시간대에 편성된 사람끼리만(쉬는 사람을 끼워 넣지 않음). 완료 표시는 유지되고, 그사이 다른 사람이 완료 표시를 눌렀어도 내가 고친 경기가 그대로면 자동으로 다시 저장합니다.
- 완료 표시: 카드를 누르면 흐려지고(자리 유지), 다시 누르면 되살아납니다. 기본 보기는 전체이고 '남은 대진'은 선택입니다. 완료 여부는 모두의 화면에 바로 공유되며, 다음 주 골고루 섞기 이력에는 그날 완료로 남은 경기만 씁니다.
- 대진 균형: 관리자가 **NTRP 레벨 갱신**(정기 모임 생성 카드)을 누르면 `data/weekly/index.json` 의 `levels` 에 선수별 레벨(NTRP, 여성은 −0.5 보정)이 저장되고, 누가 대진을 만들어도 그 값으로 양 팀 합이 비슷하게 짭니다. 모임을 만들 때도 자동 갱신됩니다. **혼복은 양쪽 남성의 NTRP가 같은 경우에만 편성하고, 잡복(여+남 대 남+남)은 여성이 가장 높은 NTRP 남성과 같은 조가 됩니다.** 레벨을 모르는 참석자(게스트, NTRP 미입력)는 3.5(여성 3.0)로 간주합니다. 잡복(여 1 + 남 3)도 같은 기준으로 양 팀 합을 맞추며(균형이 같다면 여성 파트너는 코트 내 최고 남자), 혼복 남자 NTRP 동일 규칙은 지킬 수 있을 때만 적용하고 남자가 2명뿐인 시간대처럼 불가능하면 규칙 없이 만듭니다. 화면에는 레벨이 보이지 않지만 데이터 파일에는 숫자로 들어갑니다. 게스트는 기대 경기 수(참석 시간대 기준)를 채우도록 우선 배정됩니다.
- 저장 실패 시: 화면에는 변경이 그대로 남고 "저장하지 못한 변경 N건"과 **다시 시도** 버튼이 뜹니다. 여러 건이 밀려도 순서대로 다시 보냅니다. 참석 항목은 한 모임에 80명까지입니다.
- 관리자: 정기 모임 탭 위의 **정기 모임 생성** 카드에서 날짜·코트·경기 시간·시작/종료·여복 최소를 넣고 만들기. 목록의 🗑 삭제로 지웁니다. **게시하기는 필요 없습니다** — 정기 모임 데이터는 저장 즉시 반영됩니다.
- **지금 구성 (관리자 저장)**: 정기 모임 데이터는 이 저장소의 `data/weekly/index.json`(모임 목록)과 `data/weekly/sessions/<날짜>.json`(참석·대진·완료)에 있고, **관리자 토큰**이 게시하기와 같은 방식으로 `main`·`gh-pages` 에 직접 커밋합니다. 방문자는 보기만 하며(참석은 관리자에게 알려 주면 관리자가 입력), 화면은 20초마다 갱신됩니다. 모임 다음날 0시부터는 읽기 전용.
- **멤버 직접 저장 (프록시)**: Google Apps Script 웹앱(`tools/gas-proxy/Code.gs`)을 배포하고 관리자 화면 정기 모임 → "저장 서버 주소"에 넣으면, 멤버 폰에서 참석·대진·완료를 저장할 수 있습니다. 폰에는 토큰이 없고, 프록시가 자기 토큰으로 `data/weekly/sessions/<날짜>.json` 만 커밋합니다(다른 파일은 쓸 수 없음, 값도 검증). 대진 저장은 수정 번호(rev)를 비교해 먼저 온 쪽이 남습니다.
- 로컬(`localhost`)에서는 GitHub 대신 브라우저 안 모의 저장소를 씁니다(게시하기·정기 모임 모두). `?store=live` 를 붙이면 실제 데이터를 읽습니다.

### 프록시 설정 (한 번만, 약 10분)
1. **프록시용 토큰**: https://github.com/settings/personal-access-tokens/new → Repository access: *Only select repositories* → `koozinsong/tennisweet` → Permissions → Repository permissions → **Contents: Read and write** → 생성. (관리자 토큰과 별개. 앱에는 넣지 않습니다.)
2. https://script.google.com → **새 프로젝트** → 편집기의 `Code.gs` 내용을 지우고 `tools/gas-proxy/Code.gs` 전체를 붙여넣기 → 저장(💾).
3. 왼쪽 ⚙ **프로젝트 설정** → 아래 **스크립트 속성** → 속성 추가: 이름 `GH_TOKEN`, 값 = 1 의 토큰 → 저장.
4. 오른쪽 위 **배포 → 새 배포** → 유형 선택(⚙) **웹 앱** → 실행 사용자 **나**, 액세스 권한 **모든 사용자** → 배포. 권한 확인창이 뜨면 계정 선택 → "확인되지 않은 앱" 경고에서 *고급 → (프로젝트명)(안전하지 않음)으로 이동* → 허용. **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) 복사.
5. 관리자 페이지 → 정기 모임 → 정기 모임 생성 카드 → **저장 서버 주소**에 URL 붙여넣고 **저장** → **연결 확인**이 "연결됨"이면 완료. 이제 방문자 화면에서도 참석·대진·완료가 저장됩니다.
6. 코드를 고쳤을 때: Apps Script 에서 배포 → **배포 관리** → ✏ → 버전 *새 버전* → 배포 (URL 유지). **`Code.gs` 가 바뀐 커밋 뒤에는 이 재배포를 꼭 해야 합니다** — 앱과 프록시의 `applyWeeklyOp` 는 같아야 하고(`test_local.js` 가 두 사본의 일치를 검사), 프록시가 옛 버전이면 멤버 저장에 옛 규칙이 적용됩니다. 로컬 검증: `node tools/gas-proxy/test_local.js`.

## 배포
`main` 에 push 하면 `.github/workflows/pages.yml` 이 사이트를 `gh-pages` 브랜치로 게시하고, GitHub Pages 가 그 브랜치를 서빙합니다. `data/**` 와 README 만 바뀐 push 는 재배포하지 않습니다(게시 버튼이 두 브랜치에 직접 씀). 코드 수정 후 `data/` 를 직접 고쳐 push 하는 경우에도 데이터는 `main` 기준으로 다음 코드 배포 때 gh-pages 에 반영되므로, 수동 게시는 `gh-pages` 브랜치에도 같은 파일을 넣거나 Actions 를 수동 실행(workflow_dispatch)하세요. (Settings → Pages 의 Source 가 `gh-pages` / root 인지 한 번만 확인)
